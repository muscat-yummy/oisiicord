# Oisiicord

Bun・SQLite・Web Crypto・WebSocket で動く、Discord 風の会話アプリ。ランタイム依存パッケージなし。Docker 不要。

## 起動

Bun 1.3.6 以降をインストールし、このディレクトリで実行する。

```sh
bun install --frozen-lockfile
bun start
```

`http://localhost:3000` を開く。開発時は `bun dev`。ビルド工程は不要。標準では `127.0.0.1:3000` にバインドする。DB と接続設定はアプリのフォルダ外に保存する。終了は Ctrl+C。

Windows PowerShell の Bun インストールは公式の https://bun.sh/docs/installation を参照。Docker Desktop、Node.js、Redis、PostgreSQL は不要。

公開時は `.env.example` を `.env` にコピーし、`APP_ORIGIN` を実際の HTTPS URL に変更する。Bun が `.env` を読み込む。TLS 終端と WebSocket の中継をリバースプロキシに設定する。localhost 以外の HTTP origin は起動時に拒否する。IP アドレスだけの HTTP 接続では Web Crypto とメディアの権限が使えない。

| 設定 | 既定値 | 用途 |
| --- | --- | --- |
| `PORT` | `3000` | Bun の待受ポート |
| `HOST` | `127.0.0.1` | 待受アドレス |
| `APP_ORIGIN` | `http://localhost:3000` | CSRF・WebSocket Origin 検証の基準 |
| `OISIICORD_DATA_DIR` | OS ごとのユーザーデータフォルダ | DB・設定・バックアップの保存先 |
| `DATABASE_PATH` | データフォルダ内の `oisiicord.sqlite` | DB の保存先を個別に指定 |
| `ICE_SERVERS` | `[]` | WebRTC の ICE サーバー JSON 配列 |

## 操作

1. アカウントを作成する。ユーザー名は半角英数字と `_`、3～32文字。パスワードは12文字以上。鍵はブラウザが生成し、パスワード由来の鍵で暗号化して保存する。
2. 左の `＋` からサーバーを作成する。所有数の制限はなく、所有・参加を合わせて30サーバーまで。
3. サーバー名のメニューから招待リンクを発行する。有効期限は1時間・24時間・7日間・期限なしから選択でき、利用回数も指定できる。初期設定は承認不要。必要なときだけ「参加に承認が必要」を有効にする。短いリンクから参加し、参加前の会話も読める。
4. テキストチャンネルで送信する。メッセージをポイントすると返信・リアクション・ピン留め・自分のメッセージの編集と削除が表示される。
5. 添付は入力欄の `＋`。1個25 MiB、1回5個まで。暗号化されたバイナリだけを end2end.tech にアップロードする。保存時にブラウザで復号・改変検証する。
6. DM 一覧の `＋` から相手のユーザー名を指定する。相手のメンバー欄からも DM を開始できる。
7. ボイスチャンネル、または DM の「通話」で音声通話。マイク・カメラ・画面共有を操作できる。通話は最大6接続のメッシュ型。相手が多いほど送信帯域と CPU 使用量が増える。
8. 左下の歯車からユーザー設定を開く。プロフィール、表示、音声・ビデオ、通知、アクセシビリティ、キー操作、ログイン中の端末を設定できる。画像は切り抜き位置を調整し、128×128 の WebP に変換して保存する。パスワード変更、別セッションのログアウト、暗号鍵のバックアップも操作できる。
9. サーバー名のメニューからサーバー設定を開く。アイコン・名前・説明・カラー、既定チャンネル、通知、メンバー、チャンネルの説明と並び順、招待、操作履歴を管理する。

検索は現在読み込んだ会話を端末で復号した後に実行する。通知本文には会話内容を含めない。入力中表示、未読表示、再接続後の履歴取得、狭い画面のチャンネル表示に対応する。

## 通話の接続条件

初期設定は STUN/TURN なし。同一 LAN など直接接続できる環境向け。異なる NAT、携帯回線、企業ネットワークでは自分の STUN/TURN を `ICE_SERVERS` に設定する。TURN の資格情報はクライアントに届くため、期限付き・用途限定のものを使う。STUN/TURN 自体はこのリポジトリに同梱しない。画面共有とカメラは同時送信ではなく切り替え。画面のシステム音声は未対応。

STUN の設定例（ホスト名は自分の値に変更する）：

```dotenv
ICE_SERVERS=[{"urls":"stun:stun.example.net:3478"}]
```

TURN を使う場合は、管理している TURN サーバーの期限付き認証情報をローカルの設定に追加する。認証情報をリポジトリに保存しない。

## 暗号化と改変検知

本文・添付・返信・編集・リアクション・ピン留めは AES-256-GCM で暗号化。イベントごとのランダム鍵を ECDH + HKDF で各受信者向けに包み、全体に ECDSA 署名を付ける。メンバー一覧も所有者が署名する。署名不一致や固定済み公開鍵の変更は拒否する。添付の原名・鍵・削除用パスワードは暗号化メッセージの内側に置く。

サーバーは本文の平文や秘密鍵の平文を受け取らない。参加者・チャンネル名・時刻・通信量などのメタデータはサーバーに見える。Web 配信元による JavaScript の差し替え、初回公開鍵のすり替え、端末の侵害まで防ぐ設計ではない。公開鍵透明性ログ・前方秘匿性・第三者監査は未実装。運用前に [SECURITY.md](SECURITY.md) を確認して。

Proton のゼロアクセス暗号化と鍵の検証を設計上の参考にした。Proton のライブラリ・プロトコル・監査結果を流用したものではなく、互換性もない。

## 添付 API

サーバーは接続先を `https://api.end2end.tech` に固定し、以下を使用する。

- `POST /upload`、multipart `file`：ブラウザで暗号化したデータを中継
- `GET /download?id=...`：暗号文の取得
- `GET /delete?id=...&password=...`：削除用シークレットで削除

外部 API の保存期間、容量制限、稼働状況、レート制限に依存する。削除は元に戻せない。API 障害時はエラー表示し、平文アップロードや別サービスに切り替える動作は行わない。自動検証は外部の本番 API に負荷をかけないローカル模擬 API を使う。実サービスの CORS・リダイレクト・容量上限は本番接続前に確認が必要。API が別ドメインへのダウンロードリダイレクトを返す場合は安全のため拒否する。

## 検証

```sh
bun run check
bun test
```

テストは暗号化の復号・改変拒否、vault の誤鍵拒否、複数サーバーと30参加上限、署名付き参加承認、部外者の拒否、メッセージ再送拒否、署名偽造拒否、DM の権限、削除されたメンバーのアクセス拒否、外部添付 API の模擬連携、CSRF、ログアウト後のセッション失効を確認する。CI は GitHub Actions で型確認と同じテストを実行する。41件の自動テスト（暗号化・権限・WebSocket・プロフィール・セッション・パスワード変更・データ保持・Git/ZIP更新）と、ブラウザ2つでの相互送受信・編集・リアクション・招待承認・音声トラック生成を確認済み。所有者のすり替え拒否とチャンネルごとの下書き分離もブラウザで確認した。

ブラウザテストを再現する場合は `bunx playwright install chromium` の後に `bun run test:browser`。ローカルの一時 DB とテストアカウントを作成し、終了後に DB を削除する。外部 API の実アップロードは行わない。画面確認用画像は `data/ui-test-artifacts` に保存する。Playwright は開発用依存で、通常のサーバー起動には読み込まない。

## 保存先と更新

保存先は起動ログ、または `bun run data` で確認できる。

| OS | 既定の保存先 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Oisiicord` |
| macOS | `~/Library/Application Support/Oisiicord` |
| Linux | `$XDG_DATA_HOME/oisiicord`、未設定なら `~/.local/share/oisiicord` |

`oisiicord.sqlite` にアカウント、暗号化された鍵とメッセージ、サーバー、プロフィールを保存する。`config.json` にポート・公開 URL・ICE サーバー等を保存し、アプリを入れ替えた後も読み込む。環境変数、アプリ側の `.env`、保存済み設定の順で優先する。サーバーを起動する OS ユーザーと公開 URL は更新前後で同じにする。ブラウザ内の設定と公開鍵の確認状態は同じブラウザ・同じ URL で引き継がれる。

初回の移行ではサーバーを停止し、旧 `data` と `.env` を残したまま新しいソースを重ねて `bun start` を実行する。旧 `data/oisiicord.sqlite` は固定の保存先へ自動で引き継ぐ。旧版の `.env` にある `DATABASE_PATH=./data/oisiicord.sqlite` も移行対象。元のDBは削除しない。両方の保存先に未移行のDBがある場合は、上書きせず停止する。起動ログにアプリ外のDBパスが表示されたら移行完了。以後の ZIP 更新はアプリのフォルダを入れ替えてもデータと保存済み設定が残る。

## コマンドで更新

サーバーを停止して、アプリのフォルダで実行する。

```sh
bun run update --start
```

最新版の取得、更新前のバックアップ、ソースと依存関係の更新、起動まで行う。更新だけなら `bun run update`。Git 版は `main` の fast-forward、ZIP 版は GitHub の `main` を取得する。ZIP 版では Git のインストールは不要。Bun 1.3.6 以降が必要。

DB・`.env`・ユーザーが追加したファイルは更新対象から外す。ZIP 版では更新前のソースもバックアップし、取得・展開・依存関係の準備が完了してからファイルを切り替える。更新処理中のエラーではソースを戻す。2回目以降は変更したソースを検知すると停止する。Git 版でもローカルの変更や分岐した履歴は強制上書きしない。

保存先を自分で指定する場合は、アプリ外の絶対パスを `OISIICORD_DATA_DIR` に設定する。カスタム保存先はフォルダを入れ替えた後も同じ環境変数で指定する。個別の `DATABASE_PATH` も利用でき、相対パスは起動場所ではなくアプリのルートを基準に解決する。アプリ内のカスタムパスを指定した場合は、そのフォルダを削除しないこと。

## バックアップ

```sh
bun run backup
```

保存先の `backups` に日時付きのDBを作成する。更新コマンドの実行前とDBスキーマの更新前にも自動でバックアップする。WAL にある確定済みデータを含む SQLite スナップショットを作り、整合性を確認してから保存する。稼働中の `.sqlite` ファイルだけを手動でコピーしない。自動削除は行わない。

復元するときはサーバーを停止し、現在の `.sqlite`・`-wal`・`-shm` を別フォルダへ退避してから、バックアップを起動ログのDBパスへコピーする。復元したDBはバックアップ取得時点の内容になる。`config.json` も別媒体に保存しておく。DB がなくなるとアカウントと暗号化会話を復元できず、管理者用のマスターキーはない。外部添付ファイルの実体はDBバックアップに含まれない。

`bun run test:retention` は実際のサーバーを起動し、アプリのフォルダを削除・交換した後の再ログイン、鍵の復号、暗号化メッセージとサーバーの保持、接続設定の保持、バックアップコマンドを一時フォルダで確認する。

## 画面確認

`bun run test:interface` はプロフィール画像の128×128変換、設定の保存、サーバー画像、招待承認、2ユーザー間の会話と通話を確認する。外部添付 API は暗号文を保持するローカルの模擬応答を使用する。画面は `docs/screenshots` に保存する。

設定は端末の localStorage にアカウントごとに保存する。プロフィールとサーバー情報は SQLite に保存し、共有先に反映する。入力・出力デバイスはブラウザが列挙するものを使う。入力デバイスの変更時は新しいストリームに切り替え、出力はブラウザの `setSinkId` が利用できる場合に反映する。

`TEST_UI_FOCUS=server bun run test:interface` はテーマ名、サーバー追加画面、チャンネル編集・並べ替え、既定チャンネル、通知設定の保持、期限・回数付き招待と個別失効、操作履歴、モバイル表示を確認する。

## チャンネル・ロール・会話

サーバー設定でカテゴリ、ロール、お知らせ・ルールチャンネル、カスタム絵文字を管理できる。ロールの作成・編集・付与は所有者が行う。管理者、チャンネル管理、メッセージ管理、絵文字管理、送信、音声接続の権限を設定できる。ロールカラーと名前はプロフィールで表示する。

ルール本文はルールチャンネルに投稿する。設定で同意を必須にでき、変更後は再同意を求める。お知らせ・ルールチャンネルへの投稿はメッセージ管理権限が必要。チャンネル設定でカテゴリとスローモードを変更できる。

ピンは上部のボタンから一覧を開き、元のメッセージへ移動できる。チャットのアイコンや名前からプロフィールを開く。絵文字は検索・カテゴリ・最近使ったものから選び、サーバーの画像も使える。ユーザー設定で同一投稿者のメッセージのまとめ表示と間隔を変更できる。

`<button:https://example.com>`、または `<button:https://example.com|サイトを開く>` を送るとボタンになる。実際のURLとホスト名を確認してから開く。HTTP/HTTPSのみ対応する。

`settings/icon.png` を置くとアプリアイコンが変わる。`settings/dm.mp3` を置いてDMの見出しを5回押すと、見出しが虹色になり音声を再生する。詳細は [settings/README.md](settings/README.md)。カスタムファイルはupdaterの置換対象に含めない。

新しい招待は所有者署名付きの参加権限と暗号化した過去ログの鍵を渡す。所有者がオフラインでも参加前の履歴を読める。旧形式の招待も利用できるが、旧リンクの参加は従来の承認方式なので新しく発行し直す。

`bun run test:community` はロール・カテゴリ・ルール・絵文字・ピン・プロフィール・URL確認・DM効果・スマホ表示、`bun run test:history` は所有者オフライン時の新規参加と履歴、再ログイン、削除後のアクセス拒否を実ブラウザで確認する。外部への本番アップロードは行わない。

## メンションとログイン保持

入力欄で `@` を入力するとユーザー、ロール、`@everyone` の候補が開く。上下キーと Enter、またはクリックで選ぶ。ユーザーのメンションからプロフィールを開ける。サーバーの通知は標準でメンションのみ。ユーザー設定の通知で標準値を変更でき、サーバーごとにも上書きできる。DM は通常の新着を通知する。

更新後、一度ログインすると同じブラウザではタブやブラウザを閉じても7日間のセッション中は自動復元する。ログアウトやブラウザデータの削除で保持を解除する。`bun run test:login` はタブ・ブラウザの開き直し、会話の復号、パスワード変更、別タブのログアウト、期限切れを一時プロファイルで確認する。
