# Oisiicord

Bun・SQLite・Web Crypto・WebSocket で動く、Discord 風の会話アプリ。ランタイム依存パッケージなし。Docker 不要。

## 起動

Bun 1.3 以降をインストールし、このディレクトリで実行する。

```sh
bun install --frozen-lockfile
bun start
```

`http://localhost:3000` を開く。開発時は `bun dev`。ビルド工程は不要。標準では `127.0.0.1:3000` にバインドし、`data/oisiicord.sqlite` に保存する。終了は Ctrl+C。

Windows PowerShell の Bun インストールは公式の https://bun.sh/docs/installation を参照。Docker Desktop、Node.js、Redis、PostgreSQL は不要。

公開時は `.env.example` を `.env` にコピーし、`APP_ORIGIN` を実際の HTTPS URL に変更する。Bun が `.env` を読み込む。TLS 終端と WebSocket の中継をリバースプロキシに設定する。localhost 以外の HTTP origin は起動時に拒否する。IP アドレスだけの HTTP 接続では Web Crypto とメディアの権限が使えない。

| 設定 | 既定値 | 用途 |
| --- | --- | --- |
| `PORT` | `3000` | Bun の待受ポート |
| `HOST` | `127.0.0.1` | 待受アドレス |
| `APP_ORIGIN` | `http://localhost:3000` | CSRF・WebSocket Origin 検証の基準 |
| `DATABASE_PATH` | `./data/oisiicord.sqlite` | SQLite の保存先 |
| `ICE_SERVERS` | `[]` | WebRTC の ICE サーバー JSON 配列 |

## 操作

1. アカウントを作成する。ユーザー名は半角英数字と `_`、3～32文字。パスワードは12文字以上。鍵はブラウザが生成し、パスワード由来の鍵で暗号化して保存する。
2. 左の `＋` からサーバーを作成する。作成上限はアカウントごとに1個。他人のサーバーへの参加は可能。
3. サーバー名のメニューから招待リンクを発行する。有効期限は24時間。リンクの相手が参加申請し、所有者が公開鍵の指紋を確認して承認する。
4. テキストチャンネルで送信する。メッセージをポイントすると返信・リアクション・ピン留め・自分のメッセージの編集と削除が表示される。
5. 添付は入力欄の `＋`。1個25 MiB、1回5個まで。暗号化されたバイナリだけを end2end.tech にアップロードする。保存時にブラウザで復号・改変検証する。
6. DM 一覧の `＋` から相手のユーザー名を指定する。相手のメンバー欄からも DM を開始できる。
7. ボイスチャンネル、または DM の「通話」で音声通話。マイク・カメラ・画面共有を操作できる。通話は最大6接続のメッシュ型。相手が多いほど送信帯域と CPU 使用量が増える。
8. ユーザー設定で鍵の指紋確認・暗号化鍵のバックアップ・表示名変更・通知許可・ログアウトを操作する。バックアップは暗号化された鍵の保存用で、この版にアカウント復元 UI はない。

検索は現在読み込んだ会話を端末で復号した後に実行する。通知本文には会話内容を含めない。入力中表示、未読表示、再接続後の履歴取得、狭い画面のチャンネル表示に対応する。

## 通話の接続条件

初期設定は STUN/TURN なし。同一 LAN など直接接続できる環境向け。異なる NAT、携帯回線、企業ネットワークでは自分の STUN/TURN を `ICE_SERVERS` に設定する。TURN の資格情報はクライアントに届くため、期限付き・用途限定のものを使う。STUN/TURN 自体はこのリポジトリに同梱しない。画面共有とカメラは同時送信ではなく切り替え。画面のシステム音声は未対応。

例（ダミーの接続情報なので、自分の値に変更する）：

```dotenv
ICE_SERVERS=[{"urls":"stun:stun.example.net:3478"},{"urls":"turn:turn.example.net:3478","username":"temporary-user","credential":"temporary-password"}]
```

## 暗号化と改変検知

本文・添付・返信・編集・リアクション・ピン留めは AES-256-GCM で暗号化。イベントごとのランダム鍵を ECDH + HKDF で各受信者向けに包み、全体に ECDSA 署名を付ける。メンバー一覧も所有者が署名する。署名不一致や固定済み公開鍵の変更は拒否する。添付の原名・鍵・削除用パスワードは暗号化メッセージの内側に置く。

サーバーは本文の平文や秘密鍵の平文を受け取らない。参加者・チャンネル名・時刻・通信量などのメタデータはサーバーに見える。Web 配信元による JavaScript の差し替え、初回公開鍵のすり替え、端末の侵害まで防ぐ設計ではない。公開鍵透明性ログ・前方秘匿性・第三者監査は未実装。運用前に [SECURITY.md](SECURITY.md) を確認して。

Proton のゼロアクセス暗号化と鍵の検証を設計上の参考にした。Proton のライブラリ・プロトコル・監査結果を流用したものではなく、互換性もない。

## 添付 API

サーバーは接続先を `https://api.end2end.tech` に固定し、以下を使用する。

- `POST /upload`、multipart `file`：ブラウザで暗号化したデータを中継
- `GET /download?id=...`：暗号文の取得
- `GET /delete?id=...&password=...`：削除用シークレットで削除

外部 API の保存期間、容量制限、稼働状況、レート制限に依存する。削除は元に戻せない。API 障害時はエラー表示し、平文アップロードや別サービスに切り替える動作は行わない。自動検証は外部の本番 API に負荷をかけないローカル模擬 API を使う。実サービスの CORS・リダイレクト・容量上限は本番接続前に確認が必要。API が別ドメインへのダウンロードリダイレクトを返す場合は安全のため拒否する。

## 検証

```sh
bun run check
bun test
```

テストは暗号化の復号・改変拒否、vault の誤鍵拒否、1人1サーバー制限、署名付き参加承認、部外者の拒否、メッセージ再送拒否、署名偽造拒否、DM の権限、削除されたメンバーのアクセス拒否、外部添付 API の模擬連携、CSRF、ログアウト後のセッション失効を確認する。CI は GitHub Actions で型確認と同じテストを実行する。12件の自動テスト（暗号化・権限11件、WebSocket1件）と、ブラウザ2つでの相互送受信・編集・リアクション・招待承認・音声トラック生成を確認済み。所有者のすり替え拒否とチャンネルごとの下書き分離もブラウザで確認した。

ブラウザテストを再現する場合は `bunx playwright install chromium` の後に `bun run test:browser`。ローカルの一時 DB とテストアカウントを作成し、終了後に DB を削除する。外部 API の実アップロードは行わない。画面確認用画像は `data/ui-test-artifacts` に保存する。Playwright は開発用依存で、通常のサーバー起動には読み込まない。

## バックアップ

SQLite は WAL モード。稼働中に `.sqlite` ファイルだけをコピーせず、SQLite のオンラインバックアップか停止後のバックアップを使う。ブラウザの鍵の指紋・確認状態は端末内保存で、新端末へ自動同期しない。DB を失うとアカウント、暗号化 vault、メンバー一覧、暗号化会話を失う。パスワードも鍵も復元できる管理者用マスターキーはない。
