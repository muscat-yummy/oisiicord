# Oisiicord

Bun・SQLite・Web Crypto・WebSocket で動く、Discord 風の会話アプリ。Docker 不要。

## 起動

Bun 1.3.6 以降をインストールし、このディレクトリで実行する。

```sh
bun install --frozen-lockfile
bun start
```

`http://localhost:3000` を開く。開発時は `bun dev`。ビルド工程は不要。標準では `127.0.0.1:3000` にバインドする。DB と接続設定はアプリのフォルダ外に保存する。終了は Ctrl+C。

Windows PowerShell の Bun インストールは公式の https://bun.sh/docs/installation を参照。Docker Desktop、Node.js、Redis、PostgreSQL は不要。

公開時は `.env.example` を `.env` にコピーし、`APP_ORIGIN` を実際の HTTPS URL に変更する。Bun が `.env` を読み込む。TLS 終端と WebSocket の中継をリバースプロキシに設定する。localhost 以外の HTTP origin は起動時に拒否する。IP アドレスだけの HTTP 接続では Web Crypto とメディアの権限が使えない。

| 設定 | 既定値 | 用途 |
| --- | --- | --- |
| `PORT` | `3000` | Bun の待受ポート |
| `HOST` | `127.0.0.1` | 待受アドレス |
| `APP_ORIGIN` | `http://localhost:3000` | CSRF・WebSocket Origin 検証の基準 |
| `OISIICORD_DATA_DIR` | OS ごとのユーザーデータフォルダ | DB・設定・バックアップの保存先 |
| `DATABASE_PATH` | データフォルダ内の `oisiicord.sqlite` | DB の保存先を個別に指定 |
| `ICE_SERVERS` | `[]` | WebRTC の ICE サーバー JSON 配列 |

## 操作

1. アカウントを作成する。ユーザー名は半角英数字と `_`、3～32文字。パスワードは12文字以上。鍵はブラウザが生成し、パスワード由来の鍵で暗号化して保存する。
2. 左の `＋` からサーバーを作成する。所有数の制限はなく、所有・参加を合わせて30サーバーまで。
3. サーバー名のメニューから招待リンクを発行する。有効期限は1時間・24時間・7日間・期限なしから選択でき、利用回数も指定できる。初期設定は承認不要。必要なときだけ「参加に承認が必要」を有効にする。短いリンクから参加し、参加前の会話も読める。
4. テキストチャンネルで送信する。メッセージをポイントすると返信・リアクション・ピン留め・自分のメッセージの編集と削除が表示される。
5. 添付は入力欄の `＋`。標準は1個1024 MiB、Plusは2048 MiB、1回5個まで。暗号化されたバイナリだけを end2end.tech にアップロードする。保存時にブラウザで復号・改変検証する。
6. DM 一覧の `＋` から相手のユーザー名を指定する。相手のメンバー欄からも DM を開始できる。
7. ボイスチャンネル、または DM の「通話」で音声通話。マイク・カメラ・画面共有を操作できる。通話は最大6接続のメッシュ型。相手が多いほど送信帯域と CPU 使用量が増える。
8. 左下の歯車からユーザー設定を開く。プロフィール、表示、音声・ビデオ、通知、アクセシビリティ、キー操作、ログイン中の端末を設定できる。画像は切り抜き位置を調整し、128×128 の WebP に変換して保存する。パスワード変更、別セッションのログアウト、暗号鍵のバックアップも操作できる。
9. サーバー名のメニューからサーバー設定を開く。アイコン・名前・説明・カラー、既定チャンネル、通知、メンバー、チャンネルの説明と並び順、招待、操作履歴を管理する。

検索は現在読み込んだ会話を端末で復号した後に実行する。通知本文には会話内容を含めない。入力中表示、未読表示、再接続後の履歴取得、狭い画面のチャンネル表示に対応する。

## 通話の接続条件

初期設定は STUN/TURN なし。同一 LAN など直接接続できる環境向け。異なる NAT、携帯回線、企業ネットワークでは自分の STUN/TURN を `ICE_SERVERS` に設定する。TURN の資格情報はクライアントに届くため、期限付き・用途限定のものを使う。STUN/TURN 自体はこのリポジトリに同梱しない。画面共有とカメラは同時送信ではなく切り替え。画面のシステム音声は未対応。

STUN の設定例（ホスト名は自分の値に変更する）：

```dotenv
ICE_SERVERS=[{"urls":"stun:stun.example.net:3478"}]
```

TURN を使う場合は、管理している TURN サーバーの期限付き認証情報をローカルの設定に追加する。認証情報をリポジトリに保存しない。

## 暗号化と改変検知

本文・添付・返信・編集・リアクション・ピン留めは AES-256-GCM で暗号化。イベントごとのランダム鍵を ECDH + HKDF で各受信者向けに包み、全体に ECDSA 署名を付ける。メンバー一覧も所有者が署名する。署名不一致や固定済み公開鍵の変更は拒否する。添付の原名・鍵・削除用パスワードは暗号化メッセージの内側に置く。

サーバーは本文の平文や秘密鍵の平文を受け取らない。参加者・チャンネル名・時刻・通信量などのメタデータはサーバーに見える。Web 配信元による JavaScript の差し替え、初回公開鍵のすり替え、端末の侵害まで防ぐ設計ではない。公開鍵透明性ログ・前方秘匿性・第三者監査は未実装。運用前に [SECURITY.md](SECURITY.md) を確認して。

Proton のゼロアクセス暗号化と鍵の検証を設計上の参考にした。Proton のライブラリ・プロトコル・監査結果を流用したものではなく、互換性もない。

## 添付 API

サーバーは接続先を `https://api.end2end.tech` に固定し、以下を使用する。

- `POST /upload`、multipart `file`：ブラウザで暗号化したデータを中継
- `GET /download?id=...`：暗号文の取得
- `GET /delete?id=...&password=...`：削除用シークレットで削除

外部 API の保存期間、容量制限、稼働状況、レート制限に依存する。削除は元に戻せない。API 障害時はエラー表示し、平文アップロードや別サービスに切り替える動作は行わない。自動検証は外部の本番 API に負荷をかけないローカル模擬 API を使う。サーバー中継による実サービスの送信・取得・削除を確認済み。大容量や長期保存、別環境での動作は別途確認が必要。API が別ドメインへのダウンロードリダイレクトを返す場合は安全のため拒否する。

## 検証

```sh
bun run check
bun test
```

テストは暗号化の復号・改変拒否、vault の誤鍵拒否、複数サーバーと30参加上限、署名付き参加承認、部外者の拒否、メッセージ再送拒否、署名偽造拒否、DM の権限、削除されたメンバーのアクセス拒否、外部添付 API の模擬連携、CSRF、ログアウト後のセッション失効を確認する。CI は GitHub Actions で型確認と同じテストを実行する。自動テスト（暗号化・権限・WebSocket・プロフィール・セッション・パスワード変更・データ保持・Git/ZIP更新）と、ブラウザ2つでの相互送受信・編集・リアクション・招待承認・音声トラック生成を確認済み。所有者のすり替え拒否もブラウザで確認した。

ブラウザテストを再現する場合は `bunx playwright install chromium` の後に `bun run test:browser`。ローカルの一時 DB とテストアカウントを作成し、終了後に DB を削除する。外部 API の実アップロードは行わない。画面確認用画像は `data/ui-test-artifacts` に保存する。Playwright は開発用依存で、通常のサーバー起動には読み込まない。

## 保存先と更新

保存先は起動ログ、または `bun run data` で確認できる。

| OS | 既定の保存先 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Oisiicord` |
| macOS | `~/Library/Application Support/Oisiicord` |
| Linux | `$XDG_DATA_HOME/oisiicord`、未設定なら `~/.local/share/oisiicord` |

`oisiicord.sqlite` にアカウント、暗号化された鍵とメッセージ、サーバー、プロフィールを保存する。`config.json` にポート・公開 URL・ICE サーバー等を保存し、アプリを入れ替えた後も読み込む。環境変数、アプリ側の `.env`、保存済み設定の順で優先する。サーバーを起動する OS ユーザーと公開 URL は更新前後で同じにする。ブラウザ内の設定と公開鍵の確認状態は同じブラウザ・同じ URL で引き継がれる。

初回の移行ではサーバーを停止し、旧 `data` と `.env` を残したまま新しいソースを重ねて `bun start` を実行する。旧 `data/oisiicord.sqlite` は固定の保存先へ自動で引き継ぐ。旧版の `.env` にある `DATABASE_PATH=./data/oisiicord.sqlite` も移行対象。元のDBは削除しない。両方の保存先に未移行のDBがある場合は、上書きせず停止する。起動ログにアプリ外のDBパスが表示されたら移行完了。以後の ZIP 更新はアプリのフォルダを入れ替えてもデータと保存済み設定が残る。

## コマンドで更新

サーバーを停止して、アプリのフォルダで実行する。

```sh
bun run update --start
```

最新版の取得、更新前のバックアップ、ソースと依存関係の更新、起動まで行う。更新だけなら `bun run update`。Git 版は `main` の fast-forward、ZIP 版は GitHub の `main` を取得する。ZIP 版では Git のインストールは不要。Bun 1.3.6 以降が必要。

DB・`.env`・ユーザーが追加したファイルは更新対象から外す。ZIP 版では更新前のソースもバックアップし、取得・展開・依存関係の準備が完了してからファイルを切り替える。更新処理中のエラーではソースを戻す。2回目以降は変更したソースを検知すると停止する。Git 版でもローカルの変更や分岐した履歴は強制上書きしない。`.env.example` の編集は更新を妨げない。ZIP版ではこのファイルを更新・削除の対象から外し、旧版の更新記録に含まれていてもローカルの内容を保持する。設定に使用するファイルは `.env`。

保存先を自分で指定する場合は、アプリ外の絶対パスを `OISIICORD_DATA_DIR` に設定する。カスタム保存先はフォルダを入れ替えた後も同じ環境変数で指定する。個別の `DATABASE_PATH` も利用でき、相対パスは起動場所ではなくアプリのルートを基準に解決する。アプリ内のカスタムパスを指定した場合は、そのフォルダを削除しないこと。

## バックアップ

```sh
bun run backup
```

保存先の `backups` に日時付きのDBを作成する。更新コマンドの実行前とDBスキーマの更新前にも自動でバックアップする。WAL にある確定済みデータを含む SQLite スナップショットを作り、整合性を確認してから保存する。稼働中の `.sqlite` ファイルだけを手動でコピーしない。自動削除は行わない。

復元するときはサーバーを停止し、現在の `.sqlite`・`-wal`・`-shm` を別フォルダへ退避してから、バックアップを起動ログのDBパスへコピーする。復元したDBはバックアップ取得時点の内容になる。`config.json` も別媒体に保存しておく。DB がなくなるとアカウントと暗号化会話を復元できず、管理者用のマスターキーはない。外部添付ファイルの実体はDBバックアップに含まれない。

`bun run test:retention` は実際のサーバーを起動し、アプリのフォルダを削除・交換した後の再ログイン、鍵の復号、暗号化メッセージとサーバーの保持、接続設定の保持、バックアップコマンドを一時フォルダで確認する。

## 画面確認

`bun run test:interface` はプロフィール画像の128×128変換、設定の保存、サーバー画像、招待承認、2ユーザー間の会話と通話を確認する。外部添付 API は暗号文を保持するローカルの模擬応答を使用する。画面は `docs/screenshots` に保存する。

設定は端末の localStorage にアカウントごとに保存する。プロフィールとサーバー情報は SQLite に保存し、共有先に反映する。入力・出力デバイスはブラウザが列挙するものを使う。入力デバイスの変更時は新しいストリームに切り替え、出力はブラウザの `setSinkId` が利用できる場合に反映する。

`TEST_UI_FOCUS=server bun run test:interface` はテーマ名、サーバー追加画面、チャンネル編集・並べ替え、既定チャンネル、通知設定の保持、期限・回数付き招待と個別失効、操作履歴、モバイル表示を確認する。

## チャンネル・ロール・会話

サーバー設定でカテゴリ、ロール、お知らせ・ルールチャンネル、カスタム絵文字を管理できる。ロールの作成・編集・付与は所有者が行う。管理者、チャンネル管理、メッセージ管理、絵文字管理、送信、音声接続の権限を設定できる。ロールカラーと名前はプロフィールで表示する。

ルール本文はルールチャンネルに投稿する。設定で同意を必須にでき、変更後は再同意を求める。お知らせ・ルールチャンネルへの投稿はメッセージ管理権限が必要。チャンネル設定でカテゴリとスローモードを変更できる。

ピンは上部のボタンから一覧を開き、元のメッセージへ移動できる。チャットのアイコンや名前からプロフィールを開く。絵文字は検索・カテゴリ・最近使ったものから選び、サーバーの画像も使える。ユーザー設定で同一投稿者のメッセージのまとめ表示と間隔を変更できる。

`<button:https://example.com>`、または `<button:https://example.com|サイトを開く>` を送るとボタンになる。実際のURLとホスト名を確認してから開く。HTTP/HTTPSのみ対応する。

`settings/icon.png` を置くとアプリアイコンが変わる。`settings/dm.mp3` を置いてDMの見出しを5回押すと、見出しが虹色になり音声を再生する。詳細は [settings/README.md](settings/README.md)。カスタムファイルはupdaterの置換対象に含めない。

新しい招待は所有者署名付きの参加権限と暗号化した過去ログの鍵を渡す。所有者がオフラインでも参加前の履歴を読める。旧形式の招待も利用できるが、旧リンクの参加は従来の承認方式なので新しく発行し直す。

`bun run test:community` はロール・カテゴリ・ルール・絵文字・ピン・プロフィール・URL確認・DM効果・スマホ表示、`bun run test:history` は所有者オフライン時の新規参加と履歴、再ログイン、削除後のアクセス拒否を実ブラウザで確認する。外部への本番アップロードは行わない。

## メンションとログイン保持

入力欄で `@` を入力するとユーザー、ロール、`@everyone` の候補が開く。上下キーと Enter、またはクリックで選ぶ。ユーザーのメンションからプロフィールを開ける。サーバーの通知は標準でメンションのみ。ユーザー設定の通知で標準値を変更でき、サーバーごとにも上書きできる。DM は通常の新着を通知する。

更新後、一度ログインすると同じブラウザではタブやブラウザを閉じても7日間のセッション中は自動復元する。ログアウトやブラウザデータの削除で保持を解除する。`bun run test:login` はタブ・ブラウザの開き直し、会話の復号、パスワード変更、別タブのログアウト、期限切れを一時プロファイルで確認する。

## 画面と右クリック操作

サーバーのアイコン、チャンネル、カテゴリの右クリックで操作メニューを開く。編集・作成・削除は権限がある場合だけ表示する。チャンネルの複製、並べ替え、カテゴリ間の移動、既読化、IDのコピーにも対応する。カテゴリ内でチャンネルを作ると所属を引き継ぎ、カテゴリの削除ではチャンネルを残す。サーバーの削除には名前の入力が必要。

ホームには共通のサーバーやDMのユーザーを表示する。「オンライン」「すべて」で切り替え、プロフィールやDMを開ける。更新ログは `settings/changelog.md` に自分で書いた内容を表示する。ファイルがない場合や空の場合は欄を表示しない。書式は [settings/README.md](settings/README.md) を参照。上部のメンバーボタンは画面幅にかかわらず一覧の表示・非表示を切り替える。

`bun run test:workspace` で右クリック、編集・複製・移動・削除、招待、プロフィール、オンライン一覧とモバイル表示を一時DBで確認する。

## 自分用ツールと入力候補

上部のノートアイコンから、メモ・定型文を開く。

- メモ：チャンネルやDMごとに自分用メモを保存する。
- 定型文：名前と本文を保存して挿入する。`{date}`、`{time}`、`{channel}`、`{me}` を挿入時の日付・時刻・チャンネル名・表示名に置き換える。挿入だけでは送信しない。

これらはアカウントごとに本人の鍵で暗号化して同じブラウザ内に保存し、サーバーには送信しない。別ブラウザ・別端末への同期は行わない。ブラウザのサイトデータを削除すると失われる。

入力欄で `<` を打つとリンクボタン、コードブロック、定型文の候補を開く。上下キーで移動し、Enter・Tab・クリックで挿入、Escで閉じる。リンクボタンはURLと名前を入力して作成する。クリック時のURL確認は維持する。

`bun run test:productivity` で入力候補、URL確認、メモ・定型文の保存と復元、モバイル表示を確認する。

## メッセージの書式

[Discord公式のMarkdown仕様](https://support.discord.com/hc/en-us/articles/210298617)に合わせ、行頭の `# `・`## `・`### ` で見出し、`-# ` で小さい文字を表示する。記号の後ろには半角スペースが必要。

`**太字**`、`*斜体*`・`_斜体_`、`__下線__`、`~~取り消し線~~`、`||伏せ字||`、書式の組み合わせ、`- `・`* ` のリスト、2スペースの入れ子、`1. ` の番号付きリスト、`> ` の引用、`>>> ` 以降の複数行引用に対応する。伏せ字はクリックまたはEnter・Spaceで表示する。

`[表示名](https://example.com)` で名前付きリンクを作れる。開く前に実際のURLを確認する。バックスラッシュで記号をエスケープできる。コード内の書式は変換しない。本文の保存形式・暗号化形式は変更せず、過去のメッセージとピン留めにも同じ表示を適用する。表・チェックボックス・画像のMarkdown埋め込みは追加しない。

`bun test tests/markdown.test.ts` と `bun run test:markdown` で構文と実画面を確認する。

## コード・Mermaid・添付プレビュー

メッセージを言語名付きのコードフェンスで囲むと、言語の色分け、コピー、折り返しを使える。`json` のブロックには整形・圧縮もある。コード内のメンションやリンクは文字列として表示する。

コードフェンスの言語を `mermaid` にすると図へ変換する。コードへの切り替え、拡大、SVG保存に対応する。`<` の入力候補からもコードブロックの入力画面を開ける。Mermaid内の設定変更、HTMLラベル、クリックによる外部リンクやスクリプトは無効。構文エラー時は元のコードを表示する。

PNG・JPEG・GIF・WebP・BMP、MP4・WebM・Ogg動画、MP3・WAV・Ogg/Opus・M4A・FLAC・AAC・WebM音声をチャット内でプレビューする。添付全体を取得して復号・改変検証した後に表示し、動画・音楽は自動再生しない。画像はクリックで拡大でき、元ファイルの保存もできる。SVGや対応外形式は保存操作を使う。動画・音楽のコーデック対応はブラウザに依存する。インライン画像は32メガピクセルまで、復号したプレビューの保持は最大64 MiB。

Mermaidとhighlight.jsはバージョンを固定して同梱の依存関係から自分のサーバーが配信する。CDNや外部の図変換サービスに本文を送らない。Mermaidは図が見えるとき、色分けはコードがあるときに必要なライブラリを読み込む。起動前に通常どおり `bun install --frozen-lockfile` を実行する。手動のビルド工程は不要。

`bun run test:developer` は図・SVG保存・コード表示・画像拡大・動画と音楽の再生・改変拒否・ログアウト時のプレビュー破棄をローカルの模擬添付APIで確認する。音楽のテスト用ファイル生成にはFFmpegを使う。

- [Mermaid の利用方法](https://mermaid.js.org/config/usage.html)
- [highlight.js API](https://highlightjs.readthedocs.io/en/latest/api.html)

メッセージの削除は通常は確認画面を表示し、Shiftを押しながら削除ボタンを押すと確認なしで削除する。未送信の入力はチャンネルの移動や再読み込みでは保持しない。

## 退出・ブロック・アカウント削除

サーバーメニュー・右クリック・サーバー設定から自主退出できる。所有者がオフラインでも操作でき、本人の署名付き退出証明を残りのメンバーが検証する。所有者は退出の代わりにサーバーを削除する。退出時には既存の招待を無効にするため、再参加には所有者が新しく作った招待リンクが必要になる。退出前に受け取った会話やファイルは回収できない。

プロフィールからブロック・解除できる。ブロック中は双方のDM送信・DM通話をサーバーでも拒否し、共通サーバーのメッセージは折りたたむ。通知と入力中表示を抑止し、共通通話では直接接続しない。過去のDMは保持する。解除一覧はユーザー設定の「ブロックしたユーザー」。ブロックはサーバーからの追放やチャンネル単位の閲覧制限ではない。

ユーザー設定のマイアカウントからアカウントを削除できる。ユーザー名と現在のパスワードで確認し、所有サーバーがあれば削除への同意を別に求める。プロフィール、認証情報、鍵のvault、全セッション、所属とブロック設定を削除し、現在のブラウザの本人用データも消す。残った会話を壊さないため、非所有サーバー・DMの送信済み暗号文と検証用公開鍵は匿名の記録として保持する。取得済みのコピーや過去のバックアップを遠隔消去するものではない。

DBスキーマは3。既存DBは変更前にバックアップし、トランザクションで非破壊移行する。詳細な確認結果は [docs/release-review/lifecycle.md](docs/release-review/lifecycle.md)。

- `bun run test:lifecycle`：一時DBで退出・再参加・ブロック・削除と複数タブの失効を操作する。
- `bun run test:files:live`：本番end2end.techへテスト用の128バイトを暗号化したファイル1件だけ送信し、取得・復号後に削除する。通常の `bun test` では実行しない。

## 別端末のログインで公開URLの不一致が出る場合

`.env` の `APP_ORIGIN` を、スマホで実際に開いているURLのスキーム・ホスト名・ポートに合わせる。パス・クエリ・フラグメントは含めない。末尾の `/`、ホスト名の大文字・小文字、HTTPSの省略可能な `:443` は起動時に正規化する。`www` の有無、IPアドレス、別ポートは異なるアクセス元として扱う。

変更後はOisiicordのプロセスを起動し直す。設定は環境変数、`.env`、データフォルダの `config.json` の順で優先する。リバースプロキシを使う場合も、`APP_ORIGIN` は内部のlocalhostではなく外部のHTTPS URLにする。Origin判定にはクライアントが指定したHostや転送ヘッダーを使わない。

## 公開カスタム招待URL

「友達を招待」のカスタムURL欄で、`test` など半角英小文字・数字・ハイフンの3〜32文字を指定すると、`https://公開ホスト/test` の形式で参加できる。無料で各サーバー1つ。公開URLは承認不要・期限なし・回数制限なしに固定する。他のサーバーが使用している名前とシステム用のパスは指定できない。通常の非公開招待リンクは従来どおり作れる。

公開URLは登録ユーザーなら誰でも参加できる。所有者の署名した公開参加権限を使い、参加者本人の署名を検証する。サーバーに招待の秘密鍵や履歴の復号鍵は置かない。参加後、履歴の鍵を持つ既存参加者の端末がオンラインなら、参加先の公開鍵で包んで自動共有する。既存端末がすべてオフラインの場合、過去の履歴は端末がオンラインになるまで待つ。参加・新しいメッセージの送受信に所有者の承認操作は不要。退出や所有者のメンバー更新で招待が失効した場合はカスタムURLも無効になるため、所有者が作り直す。

## レート制限・購入

登録、認証、API、送信、添付、WebSocketをトークンバケットで制限する。API全体は接続元ごとに毎分300、認証後はユーザーごとに毎分180。送信は毎分60と5秒間6件の両方を適用する。登録は1時間5件、ログインは5分12件。超過時はHTTP429と `Retry-After` を返す。WebSocketにもユーザー別の制限を適用する。

リバースプロキシからの接続元IPを使用する場合は `.env` に `TRUST_PROXY=true` を設定する。バックエンドへの接続元がループバックの場合だけ、プロキシが追加した `X-Forwarded-For` の最後のIPを使う。プロキシは外部から受けた転送ヘッダーを検証・上書きし、バックエンドのポートを外部に公開しない。未設定時は転送ヘッダーを信用しない。

LTCの購入設定は [settings/README.md](settings/README.md) を参照。未設定時は販売を無効にする。Stripeは未実装。本文・添付の暗号化方式は購入によって変わらない。

`bun test tests/beta-feedback.test.ts` でレート制限、公開招待、履歴共有、決済照合、二重反映防止、v4移行を確認する。`bun run test:feedback` はタブレットの設定スクロール、招待参加、外部リンク警告、模擬LTC購入、参加していないサーバーの受信者への絵文字表示を確認する。決済のテストは模擬BTCPayを使い、実際の送金は行わない。`bun test tests/attachments.test.ts` は仮想2GiB入力の128分割暗号化・失敗時削除・順序検証を確認する。`bun run test:large-files` は模擬ファイルAPIで32MiB超の実ファイルを送信・保存し、改変拒否も確認する。本番サービスへの2GiB送信や実機iPadでの保存は未確認。

### 大容量添付

標準は1ファイル1024MiB、買い切りPlusは2048MiBまで。受信・保存の上限は購入状態にかかわらず2048MiB。25MiBを超えるファイルは16MiBごとに個別の鍵で暗号化し、既存のend2end.tech APIへ順番に送る。ファイル名・順序・サイズ・各部分の鍵とハッシュは署名付き暗号化メッセージに含める。暗号文1リクエストの上限は従来どおり25MiB+16バイト。添付転送は全体4件・ユーザー別2件まで同時実行し、アップロードは毎分64、ダウンロードは毎分128リクエストまで。429では指定された待機時間に従って再試行する。

大容量ファイルの保存はHTTPS上のService Workerとストリームを使い、各部分のハッシュ・認証タグ・サイズを確認してからブラウザへ渡す。ファイル全体を一度にメモリへ展開しない。途中の検証に失敗すると保存を中断する。ブラウザが残した不完全なダウンロードは完成品として使わない。タブを閉じた後の転送継続や中断再開には対応しない。25MiB以下の画像・動画・音楽のプレビューは従来どおり。25MiBを超える添付は保存操作を使う。

## 横断検索

検索欄のEnter、横断検索ボタン、Ctrl/Cmd+Shift+Fで開く。無料で全参加サーバーとDMをまとめて検索でき、現在のサーバー・会話・全DMにも絞れる。送信者、日付、コード、Mermaid、添付、リンクで絞り込み、正規表現と大文字・小文字の区別にも対応する。添付はファイル名を検索し、ファイル内容は取得しない。結果から元の会話へ移動でき、JSONまたはMarkdownで結果の本文と添付情報を書き出せる。書き出しには添付の復号鍵・削除パスワードを含めない。

検索語と復号した本文は検索APIへ送らず、端末上のWeb Workerで照合する。初回は必要な暗号化履歴を取得して検証・復号するため、履歴量と回線によって時間がかかる。レート制限時は待機し、停止ボタンで次の取得を止める。ブロック中の送信者・検証に失敗したメッセージは検索に含めない。編集と削除は現在の内容に反映し、取得に失敗した会話数は結果に表示する。正規表現が1バッチ1.5秒を超えると処理用Workerを終了する。1回の検索は本文10万件・結果5000件を上限とし、超過時は途中結果とエラーを表示する。メモリ内だけに保持し、ログアウトで検索語・結果を破棄する。実際に鍵を受け取れた履歴だけを検索できる。

大容量アップロードの開始APIは認証済みアカウントの上限を確認し、利用者に結び付けた転送IDを発行する。分割位置、暗号文のサイズ、順序、二重送信を照合する。未完了の転送枠は1時間で失効する。標準からPlusへ変更すると、その後の転送から2048MiBまで送れる。既に送信した大容量添付の受信・保存にPlusは必要ない。

`bun test tests/search-and-limits.test.ts tests/attachments.test.ts` で上限・分割転送・検索条件・書き出しを確認する。`bun run test:search` は複数サーバーとDM、編集・削除、正規表現のタイムアウト、元の会話への移動、JSON保存、スマホ・タブレットを確認する。
